**关键教训（决定了后面大量"看起来是死代码"其实不能删）**：

- 方法名层面零引用 ≠ 死代码。Spring 项目中大量方法由**框架反射调用**：`@ExceptionHandler`、`@EventListener`、`@Bean`、`WebMvcConfigurer` 回调、`MetaObjectHandler`、`AuthenticationEntryPoint`、`@PostMapping` 路由方法。
- Java 代码零调用 ≠ 死字段。`@JsonAnyGetter` 这类 Jackson 注解会把 getter 变成序列化入口。
- setter 零调用 ≠ 未赋值。使用 `@AllArgsConstructor` / `@Builder` 的 VO，字段由**构造器**赋值。

## 六、扫描局限（明确未覆盖，避免"已彻底清理"的误解）

1. **同名方法掩盖**：方法级扫描以"名字"为单位，若两个类各有 `build()`，其中一个被调用会掩盖另一个的零调用。因此扫描结果是**候选**而非结论，全部经过人工复核。
2. **未扫描**：未使用的局部变量与死赋值（需数据流分析）、未使用的实体字段（MyBatis-Plus 依赖完整映射）、`*Mapper` 中依赖 BaseMapper 默认实现的方法。
3. **未穷尽动态调用**：反射、`Class.forName`、SpEL 中的字符串、前端通过字符串传入的枚举值等场景无法由静态检索覆盖。
4. 结论：**本项目不存在"完全零引用的类"**——类级扫描中所有低引用类均为 Spring 组件（`@Configuration` / `@RestController` / `@Service` / `@Mapper` / `@Component`），由容器扫描发现。
