# 6 · 运行与测试指南

## 6.1 环境要求

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 21 | 后端编译运行 |
| Maven | 3.9+ | **仓库未提供 `mvnw`**，需自行安装 |
| Node.js | 20 / 22 | `vite@6+` 要求 `^18/^20/>=22`，建议 20/22 |
| Docker | 较新版本 | 起中间件 + 跑集成测试；命令为 Compose V2 的 `docker compose` |

**端口占用检查**：`8080`（后端）、`3307`（容器 MySQL，故意避开本机 3306）、`6379`（Redis）、`9000/9001`（MinIO）、`5173/5174`（前端）、`9090/3000/3100/9080`（可观测性栈）。

换机无需额外配置：`application-dev.yml` 的 MySQL/Redis/MinIO 连接默认值与 `infra/docker-compose.yml` 兜底端口一致，`infra/.env` 可选。

## 6.2 启动步骤

### ① 基础设施

```bash
# MySQL(3307) / Redis(6379) / MinIO(9000,9001)
docker compose -f infra/docker-compose.yml up -d

# 可选：Prometheus(9090) / Grafana(3000) / Loki(3100) / Promtail(9080)
docker compose -f infra/docker-compose.yml --profile observability up -d
```

表结构与演示数据**不在这里初始化**，由后端启动时 Flyway 自动执行（V1~V13）。
MinIO 拉取失败不影响后端启动，图片上传改用本地磁盘：`--mall.storage.type=local`（文件落 `backend/uploads/`）。

### ② 后端

```bash
cd backend
mvn spring-boot:run                # 默认 dev profile，端口 8080

# 或打包运行
mvn -DskipTests clean package && java -jar target/geek-mall-server-1.0.0.jar

# 需要加载 infra/.env（如支付宝沙箱密钥）时用启动脚本（会回显生效的支付渠道）
bash scripts/run-backend.sh        # SERVER_PORT=8081 可改端口
```

启动后：

| 地址 | 用途 |
| --- | --- |
| http://localhost:8080/api/v1 | 接口前缀 |
| http://localhost:8080/swagger-ui.html | 接口文档 |
| http://localhost:8080/actuator/health | 健康检查（含秒杀队列健康） |
| http://localhost:8080/actuator/prometheus | 指标 |

### ③ 前端（两端可同时跑）

```bash
cd frontend && npm install && npm run dev            # 买家端 → http://localhost:5173
cd frontendMerchant && npm install && npm run dev    # 商家端 → http://localhost:5174
```

`/api` 已在 `vite.config.js` 代理到 `http://localhost:8080`；后端地址不同可用 `VITE_API_TARGET` 覆盖。

### ④ 演示账号（dev 启动自动创建，口令均 `123456`）

| 端 | 账号 |
| --- | --- |
| 买家端 | `13800000000` / `123456` |
| 商家端 | `merchant` / `123456` |

dev 便利开关（**生产必须关闭**）：短信验证码回显（`mall.sms.expose-code=true`）、模拟发货等联调接口（`mall.mock.enabled=true`）。

### ⑤ 以生产配置启动（本地验证用）

`prod` profile 不再提供任何安全兜底，缺配置会**直接启动失败**（这是刻意设计）：

```bash
export MALL_JWT_SECRET="$(openssl rand -base64 48)"   # 必须 ≥32 字节
export MYSQL_HOST=... MYSQL_DB=... MYSQL_USER=... MYSQL_PASSWORD=...
export REDIS_HOST=... REDIS_PASSWORD=...               # 生产不允许空口令
java -jar target/geek-mall-server-1.0.0.jar --spring.profiles.active=prod
```

启动期 `ProdConfigGuard` 会校验「JWT 密钥是否仍是源码里的公开默认值、演示账号/mock/验证码回显
是否被打开、限流是否被关闭」，任一不合规即拒绝启动并一次性列出全部问题。

## 6.3 运行测试

```bash
cd backend
mvn test
```

- 53 个测试类 + 1 基类、629 个用例；集成测试用 **Testcontainers 拉起真实 MySQL 8 + Redis 7**、执行真实 Flyway 与真实过滤器链；
- **本机 Docker 必须运行**，首次执行会拉镜像；
- 并发正确性（不超卖、一人一单、库存只回退一次、击穿只回源一次）已固化为自动化断言。

## 6.4 运行压测（可选）

```bash
# 需先安装 k6：brew install k6
bash loadtest/scripts/run_k6_order.sh   # 下单链路 + 秒杀洪峰同轮并发
bash loadtest/scripts/run_tests.sh      # 全量：重置环境→造账号→并发正确性→压测→渲染指标
```

体系组成（[loadtest/](../loadtest)）：

| 部分 | 内容 |
| --- | --- |
| `k6/` | `order.js`（普通下单）、`order-vs-seckill.js`（秒杀洪峰 vs 普通下单）、`seckill.js`/`seckill-result.js`、`read.js`、`concurrency.js` |
| `jmeter/` | `concurrency-test.jmx`（并发正确性）、`seckill-stress.jmx`、`read-stress.jmx` |
| `scripts/` | `prepare_data.py`（造账号换 JWT）、`verify_results.py`（幂等/不超卖/无系统错误校验）、`reset_env.sh`、`run_bucket_compare.sh`（分桶对比）、`queue_metrics.py`、`report_metrics.py` 等 |
| `results/` | 实测结果与报告 |

注意事项：

- 压测账号数据 `loadtest/data/users.csv`（含 JWT）**不入库**，首次压测先跑 `prepare_data.py`（`run_tests.sh` 已包含）；
- ⚠️ JWT 有效期 **2 小时**，token 过期会表现为大批 401"业务拒绝"，很像"已抢光"。

## 6.5 CI 与代码风格

- CI（`.github/workflows/ci.yml`，push/PR 触发）：
  - `backend`：Spotless 格式检查（ratchet）+ `mvn test` + 上传测试报告；
  - `frontend` / `frontendMerchant`：`npm ci` + ESLint + 构建。
- 本地前端风格检查：`bash scripts/check-frontend-style.sh`（ESLint 9 flat config + Prettier 3 ratchet）。
- 后端格式：Spotless + palantir-java-format，同样 ratchet（只约束相对 `origin/main` 改动的文件）。

## 6.6 常见问题速查

| 现象 | 处理 |
| --- | --- |
| 401 | 登录态/令牌过期；前端拦截器自动跳登录 |
| 429 | 触发限流（防刷接口为 `FAIL_CLOSED`）；规则见 `docs/spec/接口限流策略说明.md` |
| 连不上 MySQL/Redis | 中间件未启动：`docker compose -f infra/docker-compose.yml up -d` |
| `Access denied for user 'root'@'localhost'` | 连到了本机 MySQL：确认容器端口 3307，`application-dev.yml` 未被改回 3306 |
| 3307/6379 被占用 | 停本地 MySQL/Redis，或改 `.env` 的 `MYSQL_PORT`/`REDIS_PORT` 并同步后端配置 |
| 前端报 Node 版本不支持 | 升级到 Node 20/22 |
| `mvn test` 报容器错误 | Docker 未运行，或 Testcontainers 版本问题（项目固定 1.21.4） |
| 图片上传失败 | MinIO 未就绪：`--mall.storage.type=local` |
| 压测大面积失败 | 大概率压测账号 token 过期（见 6.4） |

## 6.7 多实例与可观测性（进阶）

- 多实例：`infra/docker-compose.multi.yml` + `mall.cluster.instance-count` 按实际副本数声明（影响 LOCAL 限流分摊与连接池校验）；多实例 5 项验证结论见 `docs/benchmark/多实例部署验证-2026-10-08.md`。
