# 1 · 项目整体架构

## 1.1 系统拓扑

```
┌────────────────────────────┐        ┌────────────────────────────┐
│  买家端 frontend (5173)     │        │  商家端 frontendMerchant    │
│  Vue3 + Vite + Pinia        │        │  (5174) Vue3 + Vite         │
└──────────────┬─────────────┘        └──────────────┬─────────────┘
               │  /api 代理（同源，无跨域）            │
               └──────────────┬──────────────────────┘
                              ▼
               ┌──────────────────────────────┐
               │  backend · Spring Boot 3.3.5  │  :8080
               │  统一前缀 /api/v1（132 接口）   │
               │  ┌────────────────────────┐  │
               │  │ 治理层 common/          │  │  限流 · 缓存三防 · 熔断 · 日志/Trace
               │  │ 安全层 security/        │  │  JWT 双端过滤器
               │  │ 业务层 modules/ (13 域) │  │  controller → service → mapper
               │  └────────────────────────┘  │
               └───┬─────────┬─────────┬──────┘
                   ▼         ▼         ▼
               ┌───────┐ ┌───────┐ ┌────────┐
               │ MySQL │ │ Redis │ │ MinIO  │   infra/docker-compose.yml
               │ :3307 │ │ :6379 │ │:9000/1 │   （表结构由 Flyway 自动迁移）
               └───────┘ └───────┘ └────────┘
                              │
        （可选 observability profile）▼
   Prometheus :9090 → Grafana :3000 ｜ Loki :3100 ← Promtail :9080
```

- 两个前端通过 Vite dev server 把 `/api` 代理到 `http://localhost:8080`，浏览器视角同源。
- 后端无状态（JWT），会话状态放 Redis，支持多实例水平扩展（`mall.cluster.instance-count` 声明副本数）。
- 中间件全部容器化；**表结构与演示数据由后端启动时 Flyway 自动执行**，代码与库结构同源。

## 1.2 后端分层架构

后端代码根包 `backend/src/main/java/com/geekmall/`，分为四层：

| 层 | 包 | 职责 |
| --- | --- | --- |
| 通用治理层 | `common/` | 与业务无关的横切能力：`cache`（缓存三防）、`ratelimit`（全站限流）、`resilience`（熔断降级）、`log`/`filter`（TraceId 与日志治理）、`event`、`result`、`exception`、`cluster`、`constant`、`enums`、`util` |
| 配置层 | `config/` | Spring 装配：Security、Redis/Cache、MyBatis-Plus、异步线程池、MinIO、ShedLock、OpenAPI、WebMvc 等 |
| 安全层 | `security/` | JWT 签发校验、买家/商家**双端安全上下文**、登录会话本地缓存与失效广播 |
| 业务层 | `modules/` | 13 个业务域，每域统一 `controller → service(+impl) → mapper`，配 `entity / dto / vo / converter` |

业务域一览（`modules/`）：

| 域 | 职责 | 域 | 职责 |
| --- | --- | --- | --- |
| `auth` | 登录 / 注册 / 短信验证码 | `review` | 商品评价 |
| `user` | 资料 / 地址 / 签到 / 收藏 | `aftersale` | 售后申请与处理 |
| `product` | 分类 / 列表 / 搜索 / 详情 / 首页 | `message` | 消息中心 |
| `cart` | 购物车 | `content` | CMS / 文件上传（MinIO / 本地磁盘） |
| `trade` | 结算 / 下单 / 订单状态机 / 物流 | `merchant` | 商家中心（商品/订单/售后/财务/营销/评价） |
| `payment` | 支付单 / 渠道回调 / 退款 / 沙箱支付宝 | `inventory` | 商品库存分桶（`inv_bucket` 四表） |
| `marketing` | 优惠券 / 秒杀 / 积分 | | |

## 1.3 核心请求链路

### 1.3.1 普通请求

```
HTTP 请求
  → TraceIdFilter            # 生成/透传 traceId，写入 MDC（结构化 JSON 日志）
  → RateLimitInterceptor     # 按 RateLimitPolicies 策略表限流（LOCAL 滑动窗口 / DISTRIBUTED Redis）
  → Security 过滤链           # JwtAuthenticationFilter / MerchantJwtAuthenticationFilter 解析令牌
  → Controller → Service → Mapper → MySQL
  → Result<T> 统一响应体 { code, msg, data }   # HTTP 状态恒为 200，业务结果在 body
```

### 1.3.2 秒杀抢购（削峰链路，本项目核心）

```
抢购请求 grabAsync
  → Lua 原子预占（Redis 分桶库存判定 + 幂等 requestId）
  → 受理成功 → Redis Stream 入队（MAXLEN 裁剪）→ 立即返回受理号
  → 轮询 grabResult(requestId) 取最终结果
  ── 后台 SeckillOrderConsumer（消费者组）──
  → poll → grabInTx（真实落库/扣减）→ ack
  → 超时未 ack 的消息由 reclaimStale 回收，解析失败进死信计数
```

要点：**受理与落库解耦**——落库吞吐由 DB 决定，削峰只摊平脉冲；结果通过 `SeckillResultStore` 轮询。

### 1.3.3 下单与支付

```
preOrder（结算试算）→ submit（幂等键 + requestId 去重）→ OrderStateMachine 状态流转（CAS）
  → applyPayment（PaymentChannelClient：AlipaySandboxChannel / LocalSandboxChannel）
  → 渠道回调 handleNotify（幂等）→ 订单状态机 → OrderStatusChangedEvent
  → OrderStatusMessageListener（站内消息）/ 超时由 OrderTimeoutJob 关单、PayQueryCompensationJob 主动查单补偿
```

## 1.4 高并发治理架构总览

| 能力 | 落地位置 | 机制 |
| --- | --- | --- |
| 全站限流 | `common/ratelimit/` | 规则集中在 `RateLimitPolicies` 单一策略表（132/132 端点显式分类）；默认本地滑动窗口，"限流是唯一防线"的接口走 Redis；含并发度控制与 `FAIL_OPEN`/`FAIL_CLOSED` 降级 |
| 缓存三防 | `common/cache/` | 穿透：布隆过滤器 + 空值短 TTL；击穿：跨实例互斥重建；雪崩：TTL 抖动 + 本地 L1 白名单 + 熔断降级 |
| 秒杀削峰 | `modules/marketing/queue/` | Redis Stream 消费者组 + ACK + pending 回收，"受理 + 结果轮询" |
| 幂等 | `modules/trade`、`modules/payment` 等 | 下单幂等键 + 唯一索引、支付回调幂等、优惠券领取双幂等、库存回退幂等日志 |
| 并发正确性 | `modules/trade/service/OrderStateMachine` | 订单状态 CAS 流转、商品乐观锁、按 ID 排序加锁防死锁 |
| 分布式锁 | `config/ShedLockConfig` | ShedLock 保证多实例下定时任务只执行一次 |
| 熔断降级 | `common/resilience/` | 业务级 `ResilienceGuard`，覆盖 MinIO 上传、支付宝网关、秒杀队列等资源 |
| 集群容量 | `common/cluster/` | `instance-count` 声明副本数，LOCAL 限流按实例分摊；连接池总量校验 |

## 1.5 可观测性架构

- **日志**：结构化 JSON；`TraceIdFilter` + `TraceContext` + `MdcTaskDecorator` 保证 traceId 跨线程/跨队列贯通；`SlowSqlLoggingInterceptor` 慢 SQL 阈值化（默认 200ms）；`RepeatLogThrottler` 重复异常收敛。
- **指标**：Actuator + Micrometer → `/actuator/prometheus`；自定义指标含 `mall_rate_limit_rejected_total`、`mall_seckill_queue_*`、`mall_seckill_dead_letter_total` 等。
- **健康**：`/actuator/health`，含自定义 `SeckillQueueHealthIndicator`。
- **看板/告警**：Grafana provisioning 自动装载数据源与 14 面板总览看板；Prometheus 加载 `infra/prometheus/rules/mall-alerts.yml`（7 条 / 5 组告警）。

## 1.6 部署形态

- 单机开发：`docker compose` 起中间件 + 本机跑后端与两个 Vite dev server（详见 [6-运行与测试指南](./6-运行与测试指南.md)）。
- 多实例验证：同一后端起 3 实例（`instance-count: 3`），限流全局量按实例分摊、ShedLock 单点、会话失效广播均有多实例实测（见 `docs/benchmark/多实例部署验证-2026-10-08.md`）。
- 容器化：`backend/Dockerfile`；`infra/docker-compose.multi.yml` 提供多实例编排。
