# 5 · 依赖关系

## 5.1 运行时依赖（谁需要谁才能跑）

```
frontend ──┐
frontendMerchant ──┼──► backend ──► MySQL 8    （表结构：Flyway V1~V14）
                   │         ├──► Redis 7     （会话 / 限流 / 缓存 / Stream 队列 / 分布式锁）
                   │         ├──► MinIO       （图片上传；可降级 local 磁盘）
                   │         └──► ES 8.15（可选）搜索召回；缺失时自动降级 LIKE
                   │
                   └──► /api 代理到 backend:8080
```

| 依赖 | 版本要求 | 用途 | 缺失后果 |
| --- | --- | --- | --- |
| JDK | 21 | 后端编译运行 | 无法构建 |
| Maven | 3.9+（仓库**不含 mvnw**） | 后端构建 | 无法构建 |
| Node.js | 20/22（18 亦可） | 前端构建（`vite@6+` 要求 `^18/^20/>=22`） | 前端无法启动 |
| Docker | 较新版本，Compose V2 | 起中间件；**集成测试（Testcontainers）也依赖它** | `mvn test` 失败 |
| MySQL 8 | 容器 :3307 | 持久层 | 后端启动失败 |
| Redis 7 | 容器 :6379 | 会话/缓存/队列/限流 | 后端启动失败 |
| MinIO | 容器 :9000/:9001 | 图片上传 | 可容忍：改 `--mall.storage.type=local` |
| Elasticsearch（可选） | 容器 :9200 | 商品搜索（`mall.search.engine=elasticsearch` 时才依赖） | 可容忍：自动降级回 `mysql-like` |
| k6（可选） | brew install k6 | 压测 | 仅影响压测 |

> 首次启动需联网：`mvn` 拉依赖、`npm install`、Docker 拉 `mysql:8.0` / `redis:7-alpine` / `minio` 镜像。

## 5.3 后端模块间调用依赖

### 分层依赖方向（单向，禁止逆向）

```
controller ──► service(impl) ──► mapper ──► MySQL
     │              │
     │              ├──► common/*（限流/缓存/熔断/result/exception/util）
     │              └──► 其它域的 service（跨域协作，见下）
     └──► security/*（取当前登录用户）
```

### 跨业务域协作（改接口前先看这里）

| 源域 | 依赖目标 | 场景 |
| --- | --- | --- |
| `marketing`（秒杀） | `trade`：`TradeServiceImpl.createOrderWithFixedPrice` | 消费者 `grabInTx` 真实落库 |
| `marketing` | `common/cache` + Redis Lua | 预占判定原子执行 |
| `trade` | `common/enums.OrderStatus` + `OrderStateMachine`（域内） | 所有状态变更 |
| `trade` | `payment`：`applyPayment` 后走渠道 | 支付 |
| `payment` | `trade`：状态机推进订单 | 回调/补偿后改单 |
| `message` | `common/event`：订阅 `OrderStatusChangedEvent` | 站内消息 |
| `trade` / `aftersale` | `payment`：`PaymentRefundService` | 取消/售后退款 |
| `trade` / `marketing` | `inventory`：`InventoryBucketService.deduct/rollback` | 分桶商品扣减与回退 |
| `content` | MinIO / 本地磁盘（`FileService` 双实现） | 图片上传，经 `ResilienceGuard` 熔断保护 |
| `product` | `common/cache.RedisBloomFilter` | 防穿透预热 |
| `merchant` | `trade.MerchantOrderQueryService` / `review.MerchantReviewQueryService` / `aftersale.MerchantAfterSaleQueryService` / `product.ProductStockService` / `marketing.CouponService` | 商家视角的订单/商品/售后/财务。**不再直连任何他域 mapper**（ArchUnit 守护） |
| `auth` | `user.UserService`（`findByAccount` / `createAccount` / `updatePassword`） | 登录注册改密不再直连 `SysUserMapper` |
| 多个域 | `product.ProductStockService`（`deductStock` / `restoreStock` / `findByIds`） | trade / inventory / marketing / cart / review 的库存与商品读取 |

### 横切依赖（所有域都依赖）

`Result/ResultCode/PageResult`（响应体）、`BizException + GlobalExceptionHandler`（异常）、
`SecurityUtils/MerchantSecurityUtils`（当前用户）、`TraceContext`（链路）、`RateLimitInterceptor`（限流，WebMvc 层全局生效）、
`common/enums.MerchantAftersaleStatus`（买卖双方共享的售后状态口径）。

## 5.4 数据依赖

- **库结构唯一来源**：`backend/src/main/resources/db/migration/`（V1~V13），后端启动时 Flyway 自动执行；代码与库结构同源，**不要手工改库**。
- 关键表域：用户/地址、商品/分类、购物车、订单/订单状态日志/物流、支付单/退款、优惠券/秒杀（`mkt_seckill_item.bucket_count` 与 `mkt_seckill_bucket`）、积分、评价、售后、消息、商家（结算/提现）、库存分桶（`inv_bucket` 四表）。
- 幂等与并发正确性依赖**唯一索引**（下单幂等键、支付回调、优惠券领取）与状态日志表（回退幂等），由 `V8__concurrency_hardening.sql` 等迁移保证。
- 压测数据依赖：`loadtest/data/users.csv`（含 JWT，**不入库**，`.gitignore` 排除）由 `prepare_data.py` 现场生成；JWT 有效期 2 小时。

## 5.5 中间件与外部服务依赖

| 依赖 | 被谁用 | 失败时行为 |
| --- | --- | --- |
| Redis | 会话、限流 DISTRIBUTED 层、缓存、秒杀 Stream、ShedLock、布隆过滤器 | 缓存降级不阻断（`ResilientRedisCache`）；限流按 FAIL_OPEN/FAIL_CLOSED |
| MySQL | 全部业务 | 不可用即失败 |
| MinIO | `content` 文件上传 | `ResilienceGuard` 熔断降级，可切本地磁盘 |
| 支付宝沙箱 | `payment.channel.AlipaySandboxChannel`（验签/回调/关单转退款/查单补偿） | 可切 `LocalSandboxChannel` 本地模拟 |
| Prometheus/Grafana/Loki/Promtail | 可观测（`--profile observability`） | 完全可选 |

## 5.6 工程/CI 依赖

- CI（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）：
  - `backend` job：JDK 21 + `mvn spotless:check`（ratchet 相对 origin/main）+ `mvn test`（含 Testcontainers）+ 上传 surefire 报告；
  - `frontend` job（matrix：frontend / frontendMerchant）：Node 20 + `npm ci` + `npm run lint` + 构建。
  - 因此：**后端改动会跑全量集成测试，需 Docker；前端改动受 ESLint + Prettier ratchet 约束**。
- 版本治理：Spotless（后端）与 ESLint 9 + Prettier 3（前端）均采用 **ratchet** 策略，只约束新增改动，历史全库不重排。

## 5.7 依赖关系速查：改这里会波及哪里

| 你改了… | 可能波及 |
| --- | --- |
| `RateLimitPolicies` 规则表 | `RateLimitCoverageIntegrationTest` 必须仍通过（新端点需显式分类）；`docs/spec/接口限流策略说明.md` |
| `OrderStateMachine` 流转规则 | `trade`/`payment`/`aftersale`/`merchant` 所有改单路径、状态日志、消息事件 |
| Flyway 迁移（新增 V15） | 所有环境库结构、Testcontainers 测试（跑真实迁移） |
| `Result`/响应约定 | 双前端 `request.js` 解包逻辑、`ApiError` 分支 |
| `mall.cache.*` 配置 | 缓存三防行为、Grafana 缓存面板、回源激增告警 |
| `mall.cluster.instance-count` | LOCAL 限流全局量分摊、连接池容量校验 |
| 秒杀队列（`RedisStreamSeckillOrderQueue`） | `SeckillOrderConsumer`、`SeckillQueueHealthIndicator`、`mall_seckill_queue_*` 指标与告警 |
| `ProductSearchService` 契约（`total` 口径 / 过滤条件） | 三种实现都必须同步改；`ProductSearchContractIntegrationTest` 会失败 |
| `ProductQuerySupport` 过滤逻辑 | 三引擎共用，改一处即影响 LIKE / FULLTEXT / ES 全部 |
| `ProductStockService` 的扣减语义（返回 boolean） | trade / inventory / marketing / cart / review 五处调用点、`TradeServiceImplTest` 的 mock |
| `MerchantOrderQueryService` 等场景化查询服务 | merchant 的订单/发货/财务/售后四个子域；隔离条件漏写即越权 |
| `common/enums.MerchantAftersaleStatus` | 买家侧 `AfterSaleMapper` 的 SQL 口径、商家侧 CAS 条件、`MerchantAftersaleStatusTest` |
| 新增跨域 mapper 直连 | `LayeredArchitectureTest` 立即失败（规则：跨域 mapper 必须为 0） |
