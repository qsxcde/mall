# 2 · 后端模块说明

> 代码根目录：[backend/src/main/java/com/geekmall](../backend/src/main/java/com/geekmall)
> 技术栈：Spring Boot 3.3.5 / JDK 21 / Spring Security 6 + JWT / MyBatis-Plus + Flyway / Redis 7 + Caffeine / MinIO / ShedLock

## 2.1 `common/` 通用治理层

与业务完全解耦的横切能力，是本项目投入最多的一层。

### cache — 缓存三防

| 类 | 职责 |
| --- | --- |
| [ResilientRedisCache](../backend/src/main/java/com/geekmall/common/cache/ResilientRedisCache.java) | "抗打"缓存：在 Spring `RedisCache` 之上补齐三防——穿透（空值短 TTL）、击穿（跨实例互斥重建，热点 key 失效仅一个节点回源）、雪崩（Redis 故障降级不阻断） |
| `ResilientRedisCacheManager` | 缓存管理器，装配 `ResilientRedisCache` 与 TTL/抖动策略 |
| `RedisBloomFilter` | 防穿透：挡"一定不存在"的 id，配合商品域 `ProductBloomFilterWarmer` 预热 |
| `JitterTtlFunctionFactory` | 防雪崩：按 `jitter-ratio` 给 TTL 叠加随机浮动，打散集中失效 |
| `CacheNames` / `CacheProperties` | 缓存名与 TTL、L1 白名单的集中声明（改配置不改代码） |
| `CacheGovernanceMetrics` | 缓存命中/回源/互斥重建等治理指标 |

### ratelimit — 全站限流

| 类 | 职责 |
| --- | --- |
| `RateLimitPolicies` | **全站限流规则的唯一事实来源**：`RULES` 表按"具体→笼统"顺序首匹配生效，`DEFAULT` 兜底保证无遗漏；`RateLimitCoverageIntegrationTest` 强制新端点显式分类 |
| `RateLimitInterceptor` | 执行入口：解析策略与维度 → LOCAL/DISTRIBUTED 取配额 → 拒绝写 `Retry-After` → 并发限制 → 响应头 `X-RateLimit-*` |
| `LocalRateLimiter` | 本地滑动窗口（零网络往返，默认层），容量上限 `local-max-keys` 防内存撑爆 |
| `DistributedRateLimiter` | Redis 全局限流（`RateLimitTier.DISTRIBUTED`，仅"限流是唯一防线"的接口使用） |
| `RateLimitPolicy` / `RateLimitTier` / `RateLimitDimension` / `RateLimitFallback` | 规则模型、层级（LOCAL/DISTRIBUTED）、维度（IP/用户/端点）、降级策略（FAIL_OPEN/FAIL_CLOSED） |
| `RateLimitMetrics` / `RateLimitResult` / `RateLimitException` | 指标、判定结果、429 异常 |

### resilience — 业务级熔断降级

| 类 | 职责 |
| --- | --- |
| `ResilienceGuard` | 统一入口：依赖调用、成功/失败记录、熔断判定、降级回退收敛到一处；含并发 Semaphore 与指标 |
| `CircuitBreaker` / `CircuitOpenException` | 资源级熔断器（滑动窗口 + `minimum-calls` 样本阈值）与熔断打开异常 |
| `ResilienceProperties` / `ResilienceMetrics` | 各资源熔断参数与指标 |

### log / filter — 日志与链路追踪

| 类 | 职责 |
| --- | --- |
| `TraceIdFilter` | 请求入口生成/透传 traceId 写入 MDC |
| `TraceContext` / `MdcTaskDecorator` | traceId 跨线程池、跨队列传递 |
| `SlowSqlLoggingInterceptor` | 慢 SQL 阈值化（默认 200ms 打 WARN + 计指标） |
| `RepeatLogThrottler` | 同一"异常类型 + 崩溃点"窗口内只打一次完整堆栈 |

## 2.4 `modules/` 业务域

各域统一结构：`controller/`（REST 接口）→ `service/`（接口）+ `service/impl/`（实现）→ `mapper/`（MyBatis-Plus），配 `entity/`、`dto/`、`vo/`、`converter/`。

### auth（11 文件）
`AuthController`、`AuthService(Impl)`、`SmsCodeService` —— 登录、注册、短信验证码（dev 下 `mall.sms.expose-code=true` 回显验证码）。

### user（31 文件）
`UserController`、`MemberController`、`UserService(Impl)`、`MemberService(Impl)`、`CollectionService(Impl)`、`DemoDataInitializer`（dev 启动创建演示账号）—— 资料、地址、签到、收藏、积分会员。

### product（16 文件）
`ProductController`、`CategoryController`、`HomeController`、`ProductService(Impl)`、`ProductBloomFilterWarmer`（布隆过滤器预热）—— 分类树、列表、LIKE 搜索、详情、首页楼层。

### cart（10 文件）
`CartController`、`CartService(Impl)`、`CartCleanupListener` —— 购物车增删改查、清理。

### trade（32 文件）
| 类 | 职责 |
| --- | --- |
| `TradeController` / `OrderController` / `TradeMockController` | 结算下单、订单查询、dev 联调 mock（模拟发货等） |
| `TradeService(Impl)` | 下单主流程：`preOrder` / `submit` / `doSubmit`（幂等）/ `cancel` / `closeExpiredOrders` 等 |
| `OrderStateMachine` | **所有订单状态变更的唯一入口**：合法流转校验 + CAS 更新 + 状态日志 + 发布事件 |
| `OrderService(Impl)` | 订单查询与维护 |
| `OrderTimeoutJob` | 超时订单轮询关单 |
| `OrderNoGenerator` | 订单号生成（号段发号，跨实例唯一已验证） |

### payment（20 文件）
| 类 | 职责 |
| --- | --- |
| `PaymentController` / `PaymentService(Impl)` | 支付单创建、查询、`handleNotify` 渠道回调（幂等） |
| `PaymentRefundService(Impl)` | 退款 |
| `PaymentChannelClient` + `AlipaySandboxChannel` / `LocalSandboxChannel` | 支付渠道抽象（支付宝沙箱 / 本地沙箱） |
| `AlipaySigner` / `ChannelNotify` | 验签与回调解析 |

### marketing（42 文件）
| 类 | 职责 |
| --- | --- |
| `SeckillController` / `SeckillService(Impl)` | 秒杀：`sessions`/`items`/`grab`（同步）/`grabAsync`（削峰受理）/`grabResult`（轮询）/`grabInTx`（真实落库）/`releaseReservation` |

## 2.5 resources 与数据迁移

### 配置文件

| 文件 | 说明 |
| --- | --- |
| `application.yml` | 主配置：Tomcat 120 线程 + 队列、MyBatis-Plus、`mall.*` 业务配置（JWT 120 分钟、集群 instance-count、限流开关、日志慢 SQL 200ms / 重复日志节流、缓存三防参数、熔断参数） |
| `application-dev.yml` | 默认激活；MySQL/Redis/MinIO 连接全部有默认值；演示账号自动创建；`mock.enabled=true` |
| `application-prod.yml` | 生产配置：显式关闭演示账号 / mock / 验证码回显、强制开启限流；JWT 密钥与环境变量口令**无兜底默认值**（缺失即启动失败）；MySQL 默认 `sslMode=REQUIRED` 且关闭 `allowPublicKeyRetrieval`；Actuator 只暴露 health/info/prometheus 且 `show-details=never` |
| `src/test/resources/application-test.yml` | 测试配置（Testcontainers） |

> **生产配置自检**：`config/ProdConfigGuard` 在 `prod` profile 下读取**最终生效值**
> （而非 yml 文本），一旦发现「在用源码里的公开 JWT 默认密钥、演示账号开关打开、
> mock 接口开启、验证码回显、限流被关」中的任意一项，直接拒绝启动并一次性列出全部问题。
> 之所以不只在 yml 里写死：环境变量、命令行参数、`SPRING_APPLICATION_JSON` 都能覆盖 yml，
> 只有校验生效值才拦得住。对应单测 `ProdConfigGuardTest`（10 例）。

## 2.6 测试结构

`backend/src/test/java/com/geekmall/`：

- **集成测试** `integration/`（16 个）：`AbstractIntegrationTest` 基类用 **Testcontainers 起真实 MySQL 8 + Redis 7**，跑真实 Flyway 与真实过滤器链。代表：`SeckillFlowIntegrationTest`、`SeckillAsyncIntegrationTest`、`OrderStateMachineConcurrencyIntegrationTest`（并发取消只回退一次库存）、`RateLimitCoverageIntegrationTest`（133 端点限流无遗漏）、`CacheGovernanceIntegrationTest`（击穿只回源 1 次）、`InventoryBucketIntegrationTest`、`SessionInvalidationIntegrationTest`、`PaymentSandboxIntegrationTest`、`AfterSaleFlowIntegrationTest`（审批→真实退款、退货退款资金节点、拒绝与撤销语义）、`ReviewFlowIntegrationTest`（评价→订单完成→商品评分、重复评价拦截）、`MessageAndCollectionIntegrationTest`（消息已读幂等与越权、收藏/足迹幂等）。
- **单元测试**：`common/` 各治理组件（限流、缓存、熔断、日志）、`modules/` 业务支撑类（`OrderStateMachineTest`、`AlipaySignerTest`、`OrderNoGeneratorTest` 等）。
- 共 **53 个测试类 + 1 基类，629 个用例**，`mvn test` 一键全绿（需本机 Docker 运行中）。
