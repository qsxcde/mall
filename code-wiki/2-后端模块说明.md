# 2 · 后端模块说明

> 代码根目录：[backend/src/main/java/com/geekmall](../backend/src/main/java/com/geekmall)
> 技术栈：Spring Boot 4.1.1 / JDK 21 / Spring Security 7 + JWT / MyBatis-Plus + Flyway / Redis 7 + Caffeine / MinIO / ShedLock

## 2.1 `common/` 通用治理层

与业务完全解耦的横切能力，是本项目投入最多的一层。

### cache — 缓存三防

| 类 | 职责 |
| --- | --- |
| [ResilientRedisCache](../backend/src/main/java/com/geekmall/common/cache/ResilientRedisCache.java) | "抗打"缓存：在 Spring `RedisCache` 之上补齐三防——穿透（空值短 TTL）、击穿（跨实例互斥重建，热点 key 失效仅一个节点回源）、雪崩（Redis 故障降级不阻断） |
| `ResilientRedisCacheManager` | 缓存管理器，装配 `ResilientRedisCache` 与 TTL/抖动策略 |
| `RedisBloomFilter` | 防穿透：挡"一定不存在"的 id，配合商品域 `ProductBloomFilterWarmer` 预热 |
| `JitterTtlFunctionFactory` | 防雪崩：按 `jitter-ratio` 给 TTL 叠加随机浮动，打散集中失效 |
| `CacheNames` / `CacheProperties` | 缓存名与 TTL、L1 白名单的集中声明（改配置不改代码） |
| `CacheGovernanceMetrics` | 缓存命中/回源/互斥重建等治理指标 |

### ratelimit — 全站限流

| 类 | 职责 |
| --- | --- |
| `RateLimitPolicies` | **全站限流规则的唯一事实来源**：`RULES` 表按"具体→笼统"顺序首匹配生效，`DEFAULT` 兜底保证无遗漏；`RateLimitCoverageIntegrationTest` 强制新端点显式分类 |
| `RateLimitInterceptor` | 执行入口：解析策略与维度 → LOCAL/DISTRIBUTED 取配额 → 拒绝写 `Retry-After` → 并发限制 → 响应头 `X-RateLimit-*` |
| `LocalRateLimiter` | 本地滑动窗口（零网络往返，默认层），容量上限 `local-max-keys` 防内存撑爆 |
| `DistributedRateLimiter` | Redis 全局限流（`RateLimitTier.DISTRIBUTED`，仅"限流是唯一防线"的接口使用） |
| `RateLimitPolicy` / `RateLimitTier` / `RateLimitDimension` / `RateLimitFallback` | 规则模型、层级（LOCAL/DISTRIBUTED）、维度（IP/用户/端点）、降级策略（FAIL_OPEN/FAIL_CLOSED） |
| `RateLimitMetrics` / `RateLimitResult` / `RateLimitException` | 指标、判定结果、429 异常 |

### resilience — 业务级熔断降级

| 类 | 职责 |

各域统一结构：`controller/`（REST 接口）→ `service/`（接口）+ `service/impl/`（实现）→ `mapper/`（MyBatis-Plus），配 `entity/`、`dto/`、`vo/`、`converter/`。

### user（31 文件）

### product（28 文件）
`ProductController`、`CategoryController`、`HomeController`、`ProductService(Impl)`、`ProductBloomFilterWarmer`（布隆过滤器预热）—— 分类树、列表、搜索、详情、首页楼层。

**搜索引擎抽象（`search/` 包）** —— 三种实现可切换，由 `mall.search.engine` 决定：

| 实现 | 值 | 说明 |
| --- | --- | --- |
| `LikeProductSearchService` | `mysql-like`（默认） | 三列 `LIKE '%kw%'`，零额外组件成本 |
| `FulltextProductSearchService` | `mysql-fulltext` | MySQL FULLTEXT + ngram，**必须用短语模式**才与 LIKE 语义等价 |
| `ElasticProductSearchService` | `elasticsearch` | ES 9.4，只负责召回 id，内容回表取；ES 故障自动降级回 `mysql-like` |

三者共用 `ProductQuerySupport`（过滤条件与排序）以保证 A/B 语义一致；契约由
`ProductSearchContractIntegrationTest` 锁定（同一查询在三种引擎下 `total` 与命中 id 集合必须相同）。

**索引维护的两条路径**（只在 `elasticsearch` 引擎下才有「同步」这件事）：

| 路径 | 触发 | 组件 |
| --- | --- | --- |
| 在线增量 | 商品新增/编辑/上下架/改价（事务提交后异步） | `ProductChangedEvent` → `ProductIndexSyncListener` → `ElasticProductSearchIndexer` |
| 离线全量 | 首次灌数 / 重建索引 / 对齐 `sales` | `loadtest/scripts/es_sync_products.py` |

- 事件**只带商品 id**，索引器按 id 重读数据库：重复投递/乱序投递都会收敛到「索引 = 库」，
  一条迟到的旧事件不会把索引回退到旧价格；
- 索引器只在 `mall.search.engine=elasticsearch` 时装配（其它引擎的索引就是 MySQL 本身）；
- 索引缺失时按显式 mapping 自动创建 —— 否则 ES 会用动态推断建出 `price: float` 的索引，
  不报错但从此搜不对；
- 写入失败只记告警：ES 挂了不该让商家保存不了商品，代价仅是搜索新鲜度；
- 字段口径单点定义在 `ProductIndexDocument`（`cost` 永不入索引），
  `ProductIndexDocumentTest` + `ProductIndexSyncIntegrationTest` 双重锁定。
- 已知取舍：下单扣减会 `sales + qty`，但**不逐单同步索引**（那是给下单链路加外部依赖）。
  销量排序会滞后，命中集与展示内容不受影响（ES 只返回 id，内容回表）。

**`ProductStockService`** —— 商品库存与批量读取的跨域统一入口。把
`deductStock` 的「影响行数为 0 即库存不足」判读收进商品域（返回 boolean），
避免 trade / inventory / marketing / cart / review 五个域各自理解一套；同时承载商家端商品维护（`pageByShop` / `insertProduct` / `updateWithVersion`）。

## 2.6 测试结构

`backend/src/test/java/com/geekmall/`：

- **集成测试** `integration/`（16 个）：`AbstractIntegrationTest` 基类用 **Testcontainers 起真实 MySQL 8 + Redis 7**，跑真实 Flyway 与真实过滤器链。代表：`SeckillFlowIntegrationTest`、`SeckillAsyncIntegrationTest`、`OrderStateMachineConcurrencyIntegrationTest`（并发取消只回退一次库存）、`RateLimitCoverageIntegrationTest`（134 端点限流无遗漏）、`CacheGovernanceIntegrationTest`（击穿只回源 1 次）、`InventoryBucketIntegrationTest`、`SessionInvalidationIntegrationTest`、`PaymentSandboxIntegrationTest`、`AfterSaleFlowIntegrationTest`（审批→真实退款、退货退款资金节点、拒绝与撤销语义）、`ReviewFlowIntegrationTest`（评价→订单完成→商品评分、重复评价拦截）、`MessageAndCollectionIntegrationTest`（消息已读幂等与越权、收藏/足迹幂等）。
- **单元测试**：`common/` 各治理组件（限流、缓存、熔断、日志）、`modules/` 业务支撑类（`OrderStateMachineTest`、`AlipaySignerTest`、`OrderNoGeneratorTest` 等）。
- **架构测试** `architecture/LayeredArchitectureTest`（7 条 ArchUnit 规则）—— 把分层纪律从「口头约定」变成可执行断言：
  - 当前成立、防止退化：controller 不碰 mapper；common / security 不反向依赖业务域；entity 不依赖上层；controller 不依赖 service.impl；common 不依赖 config。
  - 治理后新增：**业务域不得直连其他域的 mapper**（用编程式 API 精确判定「同域放行、跨域禁止」）；域间循环依赖数 ≤ 4（钉住上限，新增环即失败）。
- 共 **68 个测试类 + 2 基类，775 个用例**，`mvn test` 一键全绿（需本机 Docker 运行中）。
